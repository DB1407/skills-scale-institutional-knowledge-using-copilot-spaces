# OctoAcme Project Management Docs — README

Welcome — this folder centralizes OctoAcme's project management process documentation. Use these documents for onboarding, planning, execution, release, and continuous improvement. This README gives a concise overview of OctoAcme's approach, the core workflows, primary personas, communication rhythms, and quality practices. Direct links to each process doc are included so you can quickly jump to the detailed guidance.

OctoAcme runs projects through a clear lifecycle of initiation, planning, execution, release, and retrospective. Initiatives start with a lightweight Project One‑pager that clarifies the problem, measurable outcomes, stakeholders, and a go/no‑go decision. Planning converts approved initiatives into prioritized backlogs with defined acceptance criteria, a Definition of Done, and a release plan with milestones. Risks and dependencies are captured in a Risk Register and revisited during planning and weekly syncs. Core artifacts (one‑pagers, release plans, backlogs, and milestone maps) are treated as the single source of truth for decisions and status.

Execution follows an iterative, board‑driven workflow (Backlog → Ready → In Progress → In Review → QA → Done). Teams use small, focused pull requests that include issue links and acceptance criteria in PR descriptions, require automated CI checks (unit, integration, linting, security scans) and at least one approval before merging. Team rhythms — daily standups, weekly delivery syncs, sprint demos, and timeboxed planning — keep progress visible and accelerate blocker resolution. Blockers are escalated via a defined path from team triage to Project Manager → Product Lead → Sponsor when necessary.

Releases emphasize automation, layered testing, and safe deployment. Releases follow a checklist (pre‑release checks, staging verification, deployment, post‑deploy verification) and rely on a rollback/incident playbook for quick recovery. Retrospectives after sprints or releases capture action items that are added back into the backlog to drive continuous improvement. Quality practices include unit and integration tests, end‑to‑end smoke tests for critical flows, security scanning in CI, and manual QA for feature acceptance where needed.
